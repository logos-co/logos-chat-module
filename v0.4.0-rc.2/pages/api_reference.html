API reference#

The module’s public surface is its contract, rust-lib/chat_module.lidl. Everything on this page is rendered from that file, so it says exactly what a generated client can call.

For a walk-through of the calls in order – bring-up, identity, opening a conversation, sending – with working code, see building a module that uses the Chat module API on docs.logos.co.

Types are LIDL’s, not any one language’s. The primitives are tstr (text), bstr (binary), int, uint, float64, bool, any, and result – a structured success-or-error. They compose as [T] for an array, {K: V} for a map, and ?T for a value that may be absent. That set is fixed by the specification; how each maps onto a concrete type is up to the SDK generating your client.

Methods#

Calls are dispatched over the Logos IPC bus. Status-bearing methods return result: success carries any payload – a conversation id, or nothing – and failure a human-readable reason. Collection getters return an array of the named record. A method that returns a plain string returns it empty when the module has not been initialised.

init(config: ChatConfig) → result#

Bring the module up and join the delivery network.

Delivery starts asynchronously and this returns without waiting for it, so the module is not yet reachable when it succeeds. Readiness arrives as a delivery_state_changed event reaching “online”, and status() reports the state at any time. Subscribe to the events before calling this, or the early ones are missed.

Calling it again while initialised succeeds and ignores the new config, so call shutdown() first to reconfigure. The one exception is a delivery that failed before its node started: the call then starts delivery again, on its own delivery_preset. The delivery node outlives shutdown(), so a new delivery_preset does not reach it.

The account is published to the contact registry at https://devnet.chat-kc.logos.co, or at LOGOS_CHAT_CONTACT_REGISTRY_URL when the module’s environment sets it; init fails when that is unreachable.

Storage lives under the instance directory the host assigns; init fails when the host assigned none. Two instances therefore run side by side by giving each host its own session directory, and need no port coordination: the delivery node picks its own.

The first init makes this module’s account and keeps its key in the instance directory, and every later init runs as it, so the address and the display name outlive a restart. The key is stored obfuscated, not encrypted: whoever can read the instance directory can run as the account.

Each init is a new installation of that account, which the account’s log on the chat registry endorses in place of the earlier ones, so a conversation opened with the address after a restart reaches it. The log has room for about 2,380 inits, fewer for each display name set; once it is full, init fails. Conversations persist across restarts purely as history: one from a previous session reads back with its messages and history_only set. It can be labelled and deleted, but it cannot be sent into or invited to, and it has no roster, until a member invites this installation back into the group. Restoring such conversations is being worked on.

shutdown() → result#

Stop the module: end the inbound worker, drop the chat client, and close its storage. Succeeds when the module was never initialised. A later init() starts a fresh session from the persisted state, as the same account. The installation ends here: the next init’s installation replaces it, and this one’s conversations read back history_only.

get_log_path() → tstr#

The file this module is writing its log to, in the instance directory the host assigned. Empty before init, and on a host that assigned none.

health() → bool#

Liveness. Always true, and reachable without init or any lock held, so what a caller learns is whether this module answered at all: a host that lost the process fails the call instead, and a false is that failure surfacing.

get_address() → tstr#

The address of this module’s account, shared out-of-band so a peer can open a conversation with it via create_conversation. It stays the same across restarts. Empty before init.

get_display_name(address: tstr) → tstr#

The name the account at address presents itself under, from its log on the chat registry. Empty before init, while the log has not been read, and for an account that set none. Answers at once: a name not read in the last 30 minutes is read in the background, and display_name_changed reports it when it differs. An account picks its own name, so show it beside something it cannot pick, such as its address. For get_address it is the name set_display_name last published, or the one init read, and is never read from the registry.

set_display_name(display_name: tstr) → result#

Publish display_name as this account’s name, in its log on the chat registry, and raise display_name_changed for get_address. The name is public, and the log keeps every name the account has had. It is trimmed, and the call fails when nothing visible is left, when it holds a line break, a control character or a text-direction override, or when it is over 64 bytes of UTF-8. Since an empty name fails, a name can be replaced but not removed. Setting the name the account already has publishes nothing and raises nothing. A peer that read the earlier name keeps showing it until its copy is 30 minutes old and the name is asked for again. Fails before init.

create_conversation(peer_address: tstr) → result#

Open a 1:1 conversation with the peer at peer_address (their get_address). Sends the cryptographic invite; the first message follows via send_message. Returns the new conversation’s id.

create_group_conversation(name: tstr, desc: tstr) → result#

Create a group conversation with this installation as its only member; grow it with add_group_members. Every member sees the returned convo_id. name and desc are the group’s shared metadata, visible to every member; both may be empty for an unnamed group.

add_group_members(convo_id: tstr, peer_addresses: [tstr]) → result#

Invite every installation the accounts at peer_addresses endorse into an existing group conversation, in one commit. The add is committed at once and applied, with the welcomes sent, about two minutes later, unless another member’s commit for the same epoch is applied instead, which drops the whole add; each peer observes the conversation once its instance has joined. Raises conversation_updated here, and members_changed once this instance applies the add. Fails on an unknown convo_id, and while an earlier add here is still to be applied. An address that is malformed or cannot be invited fails the call and adds no one. An add naming no one, or only current members, does nothing and succeeds.

list_conversations() → [Conversation]#

Every conversation this installation holds, in no particular order — sort by last_activity_ms for a conversation list.

get_messages(convo_id: tstr) → [Message]#

The messages this installation holds for a conversation, oldest first. They survive a restart, which reads back a conversation’s newest 500. An unknown conversation reports an empty list rather than failing.

list_group_members(convo_id: tstr) → [GroupMember]#

The roster of a conversation, one GroupMember per element: committed members first, then invites this instance has not applied yet. A direct conversation reports both participants and never a pending one; an unknown conversation reports an empty roster.

get_debug_data(convo_id: tstr) → result#

What a conversation reports about itself for debugging, as a JSON object. The chat core picks the names and may change them without notice. A GroupV3 group reports its epoch and epoch_fingerprint, and members, one entry per member with its signer and sync state; this module adds the account each member’s signer acts for. Other conversations report an empty object. Fails on an unknown or history_only convo_id.

send_message(convo_id: tstr, content: tstr) → result#

Encrypt content and publish it to the conversation, then record it here and raise message_sent. Success means the message was handed to delivery_module, not that delivery sent it or that any peer received it. Fails on an unknown convo_id.

set_conversation_nickname(convo_id: tstr, nickname: tstr) → result#

Label a conversation for this installation; empty clears the label. Local only — unlike a group’s name, no other member sees it. Raises conversation_updated. Fails on an unknown convo_id.

delete_conversation(convo_id: tstr) → result#

Drop a conversation and its messages from this installation, and ignore anything that arrives for it afterwards rather than reopening it. Local only: the other members keep theirs. Raises conversation_deleted. Fails on an unknown convo_id.

status() → Status#

A snapshot of the module: how many conversations it holds, and what the delivery node is doing. Readable before init, reporting zero conversations.

Events#

Events are pushed over the lp_* IPC event channel; a consumer subscribes with on_<event>() rather than polling. They are fire-and-forget: they carry their arguments positionally, in the order listed here, and return nothing.

This is where the results of the network arrive. A call returns once the request is dispatched, so an inbound message, a peer accepting an invite, or the delivery node coming online each reach you as an event rather than as a return value. Subscribe before calling init, or the earliest ones are missed.

message_received(convo_id: tstr, content: tstr, timestamp_ms: int, sender: tstr)#

An inbound message was decrypted and recorded. sender: the sender’s account address, which its account’s log vouches for.

message_sent(convo_id: tstr, content: tstr, timestamp_ms: int, message_id: tstr)#

A message this installation sent was published and recorded. message_id: the chat core’s id for it, as get_messages reports it.

message_delivered(convo_id: tstr, message_id: tstr)#

Another member received a message this installation sent, so get_messages now reports it delivered. Raised once per message.

conversation_created(convo_id: tstr, is_outgoing: bool, peer_label: tstr, kind: tstr, name: tstr, desc: tstr)#

A conversation was opened — by a call here, or by a peer’s invite arriving. is_outgoing tells the two apart. kind: “direct” (1:1) or “group”, matching the Conversation record’s field. name, desc: the group’s shared metadata, empty for direct conversations and unnamed groups.

conversation_updated(convo_id: tstr)#

A conversation’s local metadata changed here: a nickname was set, a member was invited, a direct conversation’s peer was learned, or an invite back into a history_only conversation cleared the flag. Re-read it with list_conversations.

members_changed(convo_id: tstr)#

This instance applied a commit that changed the group’s roster. Call list_group_members for the roster it applied.

conversation_deleted(convo_id: tstr)#

A conversation was deleted on this installation.

delivery_state_changed(delivery_state: tstr, detail: tstr, delivery_adopted: bool)#

The delivery node’s state changed: “initialising”, “online”, “offline”, “error” or “stopped”, with detail carrying a human-readable reason where there is one. Reaching “online” is how a caller learns init() has finished bringing the network up. “offline” follows it while delivery reports the node Disconnected, as it does for a few seconds after a start: calls still work, and delivery keeps trying a send for a minute. delivery_adopted is as in the Status record, and settled by the time the state reaches “online”.

display_name_changed(address: tstr, display_name: tstr)#

A read of the log of the account at address found a display name other than the one get_display_name reported, or set_display_name published a new one for get_address. display_name is the new one.

Records#

The structured payloads the methods above exchange. A field marked optional may be absent.

type Conversation#

  • convo_id (tstr) – Identifies the conversation in every other call. Returned by create_conversation and create_group_conversation.

  • nickname (tstr, optional) – A label for this conversation, set with set_conversation_nickname. Local to this installation; no other member sees it.

  • message_count (int) – How many messages are kept for the conversation, across restarts, including any older than get_messages returns. It counts what was sent and received here, not everything ever sent to the conversation.

  • last_activity_ms (int) – When the most recent held message arrived, in milliseconds since the Unix epoch. Zero when the conversation has no messages.

  • kind (tstr) – “direct” (1:1) or “group”. PrivateV1 and DirectV1 are both “direct”.

  • protocol (tstr, optional) – The protocol the conversation runs, as the chat core names it, such as “DirectV1” or “GroupV3”. Absent when this installation has not recorded it.

  • peer (tstr, optional) – A direct conversation’s other side: its account’s address, as create_conversation was given it or as its first message reported it. Absent for a group, and for an invite whose first message has not arrived; conversation_updated reports when it is learned.

  • name (tstr, optional) – A group’s shared name, set at creation and identical for every member. Absent for direct conversations and unnamed groups; distinct from the local-only nickname.

  • description (tstr, optional) – A group’s shared description, set at creation alongside name and likewise the same for every member. Absent on the same terms.

  • preview (tstr, optional) – The last message’s content, truncated to 160 characters, for a conversation-list preview. Absent when the conversation has no messages.

  • history_only (bool) – True for a conversation from a previous session, kept for its history only (see init).

type Message#

  • from_self (bool) – True for a message this installation sent, false for one it received.

  • content (tstr) – The message text, decrypted.

  • timestamp_ms (int) – When the message was sent (own messages) or recorded (received ones), in milliseconds since the Unix epoch.

  • sender (tstr, optional) – Sender’s account address; unset on messages this installation sent.

  • message_id (tstr, optional) – The chat core’s id for a message this installation sent, which message_sent and message_delivered carry too. Unset on received messages.

  • delivered (bool) – True once another member received this message, which this installation sent; false until then, and on received messages. In a group it turns true with the first member who received it, not the last, and it says nothing of whether anyone read it. Only GroupV3 reports it.

type Status#

  • convo_count (int) – How many conversations this installation currently holds.

  • delivery_state (tstr) – The delivery node’s state, same vocabulary as the delivery_state_changed event: “initialising”, “online”, “offline”, “error” or “stopped”.

  • detail (tstr) – A human-readable reason for that state, empty when there is none.

  • delivery_adopted (bool) – True when delivery_module already had a node this module did not create, in its current process, with its delivery_preset; a node it created before its process restarted counts. delivery_module runs one node for every module that uses it, configured by whichever asked first, so this node keeps the settings it was created with, and they may differ from delivery_preset.

type GroupMember#

  • address (tstr) – The member’s account address.

  • pending (bool) – True while this instance has not applied the commit adding this member, so it cannot read the conversation yet. Only invites this instance sent are reported, so a member another instance invited appears once this instance applies the commit that adds them. The flag clears when this instance applies its commit, about two minutes after the add; an invite whose commit lost to another member’s concurrent commit is dropped from the roster.

type ChatConfig#

  • delivery_preset (tstr, optional) – The delivery network to create delivery_module’s node on. A node that already exists keeps its own, which Status.delivery_adopted reports. Empty or absent means “logos.test”. Ignored when the module’s environment sets LOGOS_CHAT_DELIVERY_CONFIG_PATH, a JSON file whose object is passed to delivery_module’s createNode instead.

  • log_level (tstr, optional) – How much of the chat core’s own account of a run to log: “error” | “warn” | “info” | “debug” | “trace”. Absent or unrecognised means “info”. Read once, at init: a later init leaves it as it was.
